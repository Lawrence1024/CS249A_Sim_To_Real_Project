# Pololu 3pi 2040 Digital Twin

This folder contains a simplified digital twin of the Pololu 3pi+ 2040 robot for use with Scenic and Isaac Sim.

The twin was built to support a lightweight wheeled-robot workflow in `Scenic/src/scenic/simulators/isaacsim`, with the immediate goal of getting a custom small mobile robot to load, sit on a plane, and drive under Scenic control. The model intentionally prioritizes simulator compatibility and controllability over cosmetic accuracy.

The real robot dimensions were approximated from the Pololu mechanical drawing, especially the no-shell / motor-clips configuration: overall length is about 91.2 mm, overall width is about 96.0 mm, wheel diameter is about 32.0 mm, and the rear support ball is about 12.7 mm in diameter. :contentReference[oaicite:0]{index=0}

## What this digital twin includes

The current twin is a simplified articulated robot with:

- one main chassis / board body
- two side drive wheels
- one rear support sphere
- two continuous wheel joints
- one fixed rear support joint

The outer shell and detailed electronics are intentionally omitted or simplified. This is expected. The purpose of this model is to provide a robust, controllable simulation asset, not a visually complete CAD reconstruction.

## Coordinate convention

The URDF and Scenic wrapper were built assuming:

- `x` = forward
- `y` = left
- `z` = up

In Scenic, the robot is loaded under `/World/<name>/base_link`, and that `base_link` prim is the articulation root used by the wheeled robot wrapper.

## Files in this folder

Typical contents are:

- `pololu_3pi.urdf`  
  Source URDF used to generate the robot asset.

- `usd_out/`  
  Output directory generated by Isaac Sim’s URDF importer.

- `usd_out/pololu_3pi/pololu_3pi.usd`  
  The imported USD asset used by Scenic.

Depending on future iterations, there may also be alternative URDF or USD output folders.

## Mechanical spec of the current twin

The twin currently uses the following simplified geometry and controller assumptions.

### Chassis / board

The main body is modeled as a compact board-like chassis rather than a full shell.

Nominal body dimensions used in Scenic metadata are:

- width: `0.096 m`
- length: `0.0912 m`
- height: `0.035 m`

These values are used mainly for Scenic reasoning and placement. The actual rendered geometry comes from the imported USD asset.

### Drive wheels

The model has two drive wheels:

- left wheel joint: `left_wheel_joint`
- right wheel joint: `right_wheel_joint`

Wheel diameter is approximately 32 mm, so the controller uses:

- wheel radius: `0.016 m`

### Rear support

The rear support is currently modeled as a simple sphere rather than a true passive caster assembly.

Rear support sphere diameter is approximately 12.7 mm, so the sphere radius is:

- rear support radius: `0.00635 m`

This is a deliberate simplification. It is good enough for basic motion testing, but it does not reproduce all the behavior of a real caster.

## Scenic / Isaac Sim integration

This robot was made to work with the Scenic Isaac Sim backend in this repository.

The working integration pattern is:

1. import the URDF into Isaac Sim
2. generate a USD robot asset
3. reference that USD into the stage from Scenic
4. wrap `/World/<name>/base_link` as an Isaac Sim `WheeledRobot`
5. drive it using Scenic actions and a differential controller

A plain `IsaacSimRobot` can load the USD and spawn correctly, but wheeled motion requires the robot to be wrapped as a `_WheeledRobot` and controlled through `applyWheeledController(...)`, which is how the Scenic Isaac Sim interface handles mobile robots in this repo.

## Known working wrapper configuration

The working Scenic-side configuration uses:

- articulation root: `/World/<name>/base_link`
- wheel DOF names:
  - `left_wheel_joint`
  - `right_wheel_joint`
- differential controller wheel radius: `0.016`
- differential controller wheel base: `0.064`

The robot pose is explicitly set after wrapping the preloaded USD robot, rather than relying on constructor pose arguments for a freshly created robot.

## Straight-line calibration

A small persistent steering bias was observed during long straight corridor tests.

After testing multiple trim values, the following steering correction gave the best straight-line behavior in our current setup:

- throttle: `0.03`
- steering trim: `-0.001075`

A practical baseline Scenic behavior is:

```scenic
behavior DriveStraight():
    for i in range(200):
        wait
    while True:
        take applyWheeledController(0.03, -0.001075)
